# Техническое задание

## Мобильное приложение «Чат-бот консультант по подбору комплектующих ПК»

**Проект:** PCcomponent  
**Тип продукта:** учебный мобильный прототип  
**Платформа:** Android  
**Язык интерфейса:** русский  
**Режим работы:** полностью офлайн  
**Срок разработки:** 1 месяц  
**Целевая аудитория:** начинающие пользователи, обычные покупатели и сборщики персональных компьютеров

***

## 1. Назначение проекта

Приложение предназначено для автоматизированного подбора совместимых комплектующих персонального компьютера по бюджету, назначению и требованиям пользователя.

Основным средством взаимодействия является чат-бот-консультант. Бот работает как локальная экспертная система: задаёт заранее подготовленные вопросы, анализирует ответы пользователя, выбирает подходящие компоненты из локальной базы данных и объясняет результат.

Приложение не является интернет-магазином и не выполняет заказ комплектующих. Цены и характеристики используются в демонстрационных целях и хранятся локально в JSON-файлах.

## 2. Цель разработки

Разработать мобильное Android-приложение, обеспечивающее подбор совместимой конфигурации персонального компьютера на основе пользовательских параметров с использованием чат-бота консультанта и локальной базы данных комплектующих.

## 3. Задачи проекта

1. Разработать удобный тёмный интерфейс приложения.
2. Сформировать локальную базу данных комплектующих в формате JSON.
3. Реализовать каталог комплектующих с просмотром характеристик.
4. Реализовать сценарий подбора конфигурации через чат-бота.
5. Реализовать подбор компонентов по бюджету и назначению ПК.
6. Реализовать проверку базовой совместимости компонентов.
7. Реализовать расчёт общей стоимости и энергопотребления.
8. Реализовать вывод пояснений и предупреждений.
9. Реализовать сравнение конфигураций.
10. Провести модульное и инструментальное тестирование приложения.

## 4. Ограничения проекта

- Приложение работает без подключения к интернету.
- Регистрация и авторизация пользователей не предусмотрены.
- Серверная часть и облачная база данных не используются.
- Данные о комплектующих не синхронизируются автоматически с DNS или другими магазинами.
- Цены являются фиксированными учебными значениями.
- История переписки и облачное хранение не реализуются.
- Прогнозирование FPS в играх не входит в обязательный функционал.
- Приложение ориентировано на смартфоны в портретной ориентации.

## 5. Функциональные требования

### 5.1. Запуск и главное меню

При запуске приложение должно отображать главное меню со следующими разделами:

- «Начать подбор»;
- «Каталог комплектующих»;
- «Сравнение сборок»;
- «Сохранённые конфигурации»;
- «Настройки»;
- «О приложении».

### 5.2. Подбор конфигурации

Пользователь должен иметь возможность:

1. Выбрать сценарий использования:
   - игровой компьютер;
   - офисный компьютер;
   - компьютер для учёбы;
   - рабочая станция;
   - компьютер для монтажа;
   - универсальный компьютер.
2. Указать бюджет.
3. Выбрать требуемый уровень производительности:
   - базовый;
   - средний;
   - высокий.
4. Указать необходимость будущего обновления.
5. Ответить на уточняющие вопросы чат-бота.
6. Получить готовую конфигурацию.

### 5.3. Чат-бот

Чат-бот должен:

- отображать сообщения пользователя и консультанта;
- задавать вопросы по шагам;
- предоставлять варианты ответов в виде кнопок;
- имитировать небольшую задержку ответа;
- объяснять причины выбора компонентов;
- предупреждать о превышении бюджета;
- сообщать о несовместимости;
- предлагать бюджетный, оптимальный или производительный вариант;
- переводить пользователя к итоговой конфигурации.

Свободный ввод произвольных вопросов не входит в MVP. Обработка диалога выполняется по заранее заданному конечному автомату состояний.

### 5.4. Каталог комплектующих

Каталог должен содержать следующие категории:

- процессоры;
- материнские платы;
- видеокарты;
- оперативная память;
- SSD-накопители;
- HDD-накопители;
- блоки питания;
- корпуса;
- системы охлаждения.

Для каждого компонента отображаются:

- название;
- производитель;
- категория;
- цена;
- основные технические характеристики;
- уровень производительности;
- энергопотребление;
- краткое описание.

В каталоге должны быть доступны фильтрация по категории и просмотр подробной информации.

### 5.5. Проверка совместимости

Приложение должно проверять:

- соответствие сокета процессора и материнской платы;
- соответствие типа оперативной памяти;
- совместимость частоты и объёма оперативной памяти с материнской платой;
- достаточность мощности блока питания;
- соответствие форм-фактора материнской платы корпусу;
- соответствие длины видеокарты допустимой длине корпуса;
- совместимость системы охлаждения с процессором;
- наличие обязательных компонентов;
- отсутствие превышения заданного бюджета.

Результат проверки должен иметь один из статусов:

- «Совместимо»;
- «Есть предупреждения»;
- «Несовместимо».

### 5.6. Расчёты

Приложение должно рассчитывать:

- стоимость каждого компонента;
- итоговую стоимость конфигурации;
- суммарное энергопотребление;
- рекомендуемую мощность блока питания с запасом;
- условный уровень производительности.

Рекомендуемая мощность блока питания рассчитывается по формуле:

```text
Рекомендуемая мощность = (суммарное энергопотребление × 1,3)
```

Полученное значение округляется вверх до ближайшего стандартного значения мощности.

### 5.7. Экран результата

Экран результата должен содержать:

- название конфигурации;
- назначение компьютера;
- список выбранных компонентов;
- цену каждого компонента;
- итоговую стоимость;
- уровень производительности;
- расчёт энергопотребления;
- рекомендуемую мощность блока питания;
- результат проверки совместимости;
- комментарии чат-бота;
- преимущества и возможные ограничения конфигурации;
- кнопку ручного редактирования компонентов;
- кнопку добавления конфигурации к сравнению.

### 5.8. Ручное редактирование

Пользователь должен иметь возможность заменить выбранный компонент на другой компонент той же категории.

После замены приложение повторно выполняет:

- проверку совместимости;
- пересчёт стоимости;
- пересчёт энергопотребления;
- обновление предупреждений.

### 5.9. Сравнение конфигураций

Пользователь должен иметь возможность сравнить минимум две конфигурации по следующим параметрам:

- итоговая стоимость;
- уровень производительности;
- энергопотребление;
- назначение;
- совместимость;
- состав компонентов.

### 5.10. Сохранённые конфигурации

В рамках локальной работы приложения допускается хранение не более нескольких последних конфигураций на устройстве.

Сохранение может быть реализовано локально в памяти приложения или отдельным JSON-файлом. Обязательная синхронизация между устройствами не требуется.

### 5.11. Настройки

Экран настроек должен содержать:

- информацию о приложении;
- версию приложения;
- описание режима офлайн;
- кнопку очистки локальных сохранённых данных.

## 6. Нефункциональные требования

### 6.1. Интерфейс

- Использовать только тёмную тему.
- Применить плоский современный дизайн.
- Использовать контрастные цвета и читаемые размеры текста.
- Основные действия должны быть доступны не более чем за 2-3 нажатия.
- Все элементы интерфейса должны корректно отображаться на экране смартфона.
- Системный язык приложения - русский.

### 6.2. Производительность

- Основные экраны должны открываться без заметной задержки.
- Данные JSON должны загружаться один раз и переиспользоваться в памяти.
- Подбор конфигурации не должен требовать интернет-соединения.

### 6.3. Надёжность

- Некорректные или неполные данные не должны приводить к аварийному завершению приложения.
- При отсутствии подходящей конфигурации приложение должно показать понятное сообщение и предложить изменить параметры.
- Ошибки загрузки JSON должны обрабатываться с отображением сообщения пользователю.

### 6.4. Переносимость

Проект должен собираться в Android Studio на другом компьютере при наличии установленного Android SDK и Gradle-зависимостей. Не следует использовать платные сервисы, закрытые API и обязательные внешние ключи доступа.

## 9. Структура данных комплектующего

Каждая запись JSON должна содержать общий набор полей:

```json
{
  "id": 1,
  "category": "CPU",
  "name": "AMD Ryzen 5 7600",
  "brand": "AMD",
  "price": 18999,
  "performanceLevel": 3,
  "powerConsumptionW": 65,
  "description": "Процессор для игровых и универсальных компьютеров",
  "socket": "AM5"
}
```

Дополнительные поля зависят от категории:

- процессор: сокет, количество ядер, количество потоков;
- материнская плата: сокет, чипсет, форм-фактор, тип памяти;
- видеокарта: объём видеопамяти, длина, энергопотребление;
- оперативная память: тип, объём, частота;
- накопитель: тип, объём, интерфейс;
- блок питания: мощность, сертификат;
- корпус: форм-фактор, максимальная длина видеокарты;
- охлаждение: поддерживаемые сокеты, максимальный TDP, высота.

Минимальный объём демонстрационной базы - 100 записей комплектующих.

## 10. Логика подбора

Алгоритм подбора выполняется в следующем порядке:

1. Получить параметры пользователя.
2. Определить профиль использования.
3. Определить требуемый уровень производительности.
4. Разделить бюджет между категориями компонентов.
5. Выбрать подходящий процессор.
6. Выбрать материнскую плату с совместимым сокетом.
7. Выбрать оперативную память совместимого типа.
8. Выбрать видеокарту, если она нужна для сценария.
9. Выбрать накопитель.
10. Выбрать корпус, систему охлаждения и блок питания.
11. Проверить совместимость.
12. Рассчитать стоимость и энергопотребление.
13. При превышении бюджета заменить компоненты на более доступные.
14. Сформировать объяснение результата.

При равном соответствии нескольким компонентам предпочтение отдаётся:

1. совместимому компоненту;
2. компоненту, укладывающемуся в бюджет;
3. компоненту с более высоким уровнем производительности;
4. компоненту с меньшим энергопотреблением.
